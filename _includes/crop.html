{%- comment -%} A 1:1 crop of a render, shown at one source pixel per device pixel. The crop is one file. Its width and height attributes are half its pixel size, so a 2x display shows each file pixel on one device pixel; at 1 dppx a rule in style.css gives it the full pixel size from --crop-w and --crop-h, so a 1x display shows it 1:1 too, without JavaScript. assets/js/render.js sizes the image for other pixel ratios. On a window narrower than the crop the crop scrolls sideways inside .render-scroll; it is never scaled. With an HDR AVIF (hdr) a offers it to HDR displays and the PNG stays the fallback. The image links to the full frame (full) or to the crop itself. Usage, from _data/renders.yml: {% include crop.html id="super-mario-bros-sony-pvm-14l2-hill" %} or with every field given (the gallery pages do this with manifest data): {% include crop.html file="assets/.../crop-sdr.png" hdr="assets/.../crop-hdr.avif" width=1500 height=1124 x=1170 y=1168 frame_width=3840 frame_height=2880 full="assets/.../still-sdr.png" game="Metroid" scene="Brinstar start" preset="sony_pvm_14l2" signal="composite" %} Fields: file (required, a PNG with even width and height), hdr, width and height (the crop's pixel size; required), x and y (its position in the frame), frame_width and frame_height, full, game, scene, preset (an id from the hero manifest or _data/presets.yml) or preset_name, signal, alt (default: game, scene and preset), note (one sentence after the caption fields), caption (replaces the generated caption), anchor (id of the figure). In _data/renders.yml the same fields are named file, hdr, full, game, scene, preset, preset_name, signal, alt, note, caption, and crop: [x, y, width, height] and frame: [width, height]. {%- endcomment
